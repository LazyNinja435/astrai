# Commits

## Rule: Atomic Commits

Each commit should be a single logical change. Do not batch unrelated changes.

## Rule: Commit Message Quality

- Imperative mood: "Add" not "Added"
- First line under 72 characters
- Explain *why*, not just *what*, in the body
- Reference issues or tickets when applicable

## Rule: No Commit of Work-in-Progress

Do not commit code that is known to be broken, incomplete, or failing tests. If you need to save work, use stashing or a WIP branch.

## Rule: Sign Your Commits

If the project requires signed commits, comply.
