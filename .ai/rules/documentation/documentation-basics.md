# Documentation Basics

## Rule: Docs Live With Code

Documentation files are part of the project repository, updated in the same changeset as the code they document.

## Rule: Keep Docs Current

When changing code, update corresponding documentation. Outdated docs are worse than no docs.

## Rule: Write for the Reader

Clear, plain language. Assume reader is competent but unfamiliar with this specific codebase. Provide context and motivation.

## Rule: Structure Docs

Headings for scannability, important information first, code blocks with language tags, working examples.

## Rule: Document Intent

Explain *why* and *when*, not just *what*. What problem does the code solve? When to use it and when not to?

## Rule: No Placeholders

Do not create empty documentation files or sections with "TODO" or "Coming soon."
