# Skill: Release Notes

## Purpose

Write clear, user-friendly release notes that communicate what changed, why it matters, and what action is needed.

## When to Use

- Preparing a new release
- After completing a significant milestone
- User asks for release notes

## Required Inputs

- Changelog or list of changes
- Release version
- Target audience (users, developers, etc.)

## Workflow

1. Categorize changes: features, fixes, improvements, breaking changes, deprecations
2. Write a brief summary of the release
3. For each category, list changes with clear descriptions
4. Highlight breaking changes prominently with migration guidance
5. Thank contributors if applicable
6. Verify all links and references

## Output

Release notes ready for publication.

## Forbidden

- Copying raw commit messages without editing
- Downplaying breaking changes
- Including internal implementation details users don't need
