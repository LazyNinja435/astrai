# Skill: Story Splitting

## Purpose

Break large user stories into smaller, independently valuable stories. Enables incremental delivery and reduces risk.

## When to Use

- A story is too large for a single iteration
- A story has multiple acceptance criteria that can be delivered separately
- Reducing risk by delivering value incrementally

## Required Inputs

- The large story with acceptance criteria
- Business context and priorities

## Workflow

1. Review the large story and its acceptance criteria
2. Identify natural splits: by workflow step, by data variation, by user role
3. Ensure each split story delivers independent value
4. Reorder split stories by priority and dependency
5. Verify each split story has its own acceptance criteria

## Output

A set of smaller, independent stories ready for implementation.

## Forbidden

- Splitting into stories that don't deliver independent value
- Creating technical tasks disguised as user stories
- Splitting so finely that stories lose meaning
